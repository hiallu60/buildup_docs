# 주요 기술 결정

## 1. Flyway 기반 DB 버전 관리

- **결정:** 테이블과 제약 변경을 버전이 붙은 SQL 마이그레이션으로 관리합니다.
- **이유:** 로컬과 배포 DB에 같은 변경을 같은 순서로 재현하고 적용 이력을 확인하기 위해서입니다.
- **결과:** 적용된 마이그레이션은 수정하지 않고, 다음 변경은 새 버전 파일로 추가합니다.

## 2. BCrypt 비밀번호 암호화

- **결정:** 사용자 비밀번호는 BCrypt 해시로만 저장합니다.
- **이유:** 원문 비밀번호를 복구하거나 DB에서 직접 확인할 수 없게 하고, 반복 연산으로 대입 공격 비용을 높이기 위해서입니다.
- **결과:** 로그인 시 원문을 복호화하지 않고 입력값과 저장된 해시의 일치 여부를 검사합니다.

## 3. Access JWT·Refresh Token 분리

- **결정:** 짧게 사용하는 Access JWT와 장기간 로그인 유지를 위한 Refresh Token을 분리합니다.
- **이유:** 매 요청의 인증은 빠르게 처리하면서 Access Token 유출 시 피해 시간을 제한하기 위해서입니다.
- **결과:** 현재 Access JWT는 15분, Refresh Token은 14일이며 Access Token 만료가 곧 재로그인을 뜻하지는 않습니다.

## 4. Refresh Token 해시 저장·Rotation

- **결정:** Refresh Token은 원문이 아닌 SHA-256 해시로 DB에 저장하고, 갱신할 때마다 새 토큰으로 교체합니다.
- **이유:** DB 유출 시 원문 토큰 사용을 어렵게 하고 탈취된 이전 토큰의 재사용을 감지하기 위해서입니다.
- **결과:** 폐기된 토큰 재사용이 감지되면 해당 사용자의 활성 Refresh Token을 폐기할 수 있으며, 클라이언트는 갱신 요청을 동시에 여러 번 보내지 않아야 합니다.

## 5. 당시 처리자 정보·실제 사용자 FK 동시 보존

- **결정:** 승인·반려와 자재 처리 이력에 당시 표시용 처리자 정보와 실제 사용자 FK를 함께 저장합니다.
- **이유:** 사용자의 이름이나 소속이 나중에 바뀌어도 당시 기록을 유지하면서 현재 사용자와의 관계도 추적하기 위해서입니다.
- **결과:** 이력 화면은 당시 값을 표시할 수 있고, 관리·감사 기능은 실제 사용자 연결을 활용할 수 있습니다.
