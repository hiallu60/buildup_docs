# 프론트엔드 연동 방법

## 연결 원칙

- 프론트엔드는 RDS가 아니라 EC2의 백엔드 API에 연결합니다.
- API 주소는 환경변수로 관리하고 소스에 고정하지 않습니다.
- DB 계정, DB 비밀번호, JWT Secret은 프론트엔드에서 사용하지 않습니다.

```env
VITE_API_BASE_URL=https://api.example.com
```

React Native는 사용하는 환경 설정 방식에 맞춰 같은 API 기준 주소를 주입합니다.

## 인증 처리

1. 로그인 응답의 Access Token으로 보호 API를 호출합니다.
2. 요청 헤더에 `Authorization: Bearer {accessToken}`을 추가합니다.
3. `401`과 Access Token 만료를 구분해 Refresh API를 한 번 호출합니다.
4. 갱신 성공 시 새 Access Token과 Refresh Token을 모두 교체합니다.
5. 갱신 실패 시 저장한 토큰을 제거하고 로그인 화면으로 이동합니다.

동시에 여러 요청이 `401`을 받아도 Refresh 요청은 하나만 실행하고, 나머지 요청은 그 결과를 기다리도록 구현하는 것을 권장합니다.

## 권한 처리

- 전역 권한은 계정 수준 권한입니다.
- 현장별 역할은 해당 현장 안에서만 유효합니다.
- 화면에서 버튼을 숨기는 것만으로 보안을 대신할 수 없으며, 최종 권한 검사는 서버가 수행합니다.
- `403`은 권한 부족, `404`는 대상이 없거나 현재 사용자가 볼 수 없는 경우로 처리합니다.

## 현재 팀 접근 방식

- 현재 API는 EC2 8080 포트에서 실행됩니다.
- 보안 그룹에 허용된 IP만 접근할 수 있습니다.
- 프론트 개발자의 네트워크 IP가 바뀌면 규칙 갱신이 필요할 수 있습니다.
- 브라우저 웹 프론트의 Origin은 서버 CORS 허용 목록에도 등록해야 합니다.
- HTTPS와 도메인이 적용되기 전에는 민감한 실사용 데이터를 전송하지 않습니다.

## 파일과 알림

- 보고서 사진·첨부파일은 현재 DB 메타데이터 구조만 준비되어 있습니다.
- 실제 파일 업로드·다운로드는 S3 도입 후 프론트 계약을 확정합니다.
- 디바이스 토큰 등록·삭제 API는 구현되어 있지만 실제 FCM 푸시 발송은 후속 작업입니다.

## 연동 시작 순서

1. `/api/health`로 접속 여부를 확인합니다.
2. 회원가입·로그인·토큰 갱신을 연결합니다.
3. 현장 목록과 상세, 현장 가입을 연결합니다.
4. 공정과 보고서 승인 흐름을 연결합니다.
5. 자재 요청과 알림을 연결합니다.
6. 각 단계에서 `401`, `403`, `404`, `409` 화면 처리를 확인합니다.
