# 1차 배포 기능 정리

## 배포 목적

1차 배포는 프론트엔드 팀이 실제 서버를 대상으로 핵심 업무 흐름을 연동하고 검증할 수 있는 백엔드 기준점을 만드는 데 목적이 있습니다.

## 구현 완료

### 인증과 사용자

- 회원가입, 로그인, 내 정보 조회
- BCrypt 비밀번호 암호화
- Access JWT 발급과 인증
- Refresh Token 갱신, Rotation, 로그아웃
- 회원가입 기본 전역 권한 `USER`

### 현장과 구성원

- 현장 생성, 목록, 상세 조회
- 참여 코드로 현장 가입
- 현장 구성원 조회 및 현장 역할 변경
- 현장 참여 여부와 역할에 따른 접근 제어

### 공정

- 현장별 공정 생성, 목록 조회, 수정
- 중복 및 권한 오류 처리
- 승인된 보고서의 진행률을 공정에 반영

### 보고서

- 보고서 작성, 목록, 상세 조회
- 승인과 반려
- 승인·반려 이력 및 당시 처리자 정보 보존
- 반려 시 공정 진행률 미반영, 승인 시 진행률 반영

### 자재 요청

- 자재 요청 작성, 목록, 상세 조회
- 상태 변경과 처리 이력 조회
- 요청 항목과 이벤트 기록

### 알림과 디바이스 토큰

- 알림 목록, 미읽음 개수, 단건 읽음, 전체 읽음
- 디바이스 토큰 등록과 삭제
- 실제 FCM 푸시 발송은 아직 포함하지 않음

## 배포 구성

- EC2: Spring Boot 애플리케이션을 `systemd` 서비스로 실행
- RDS: 퍼블릭 접근을 차단한 MySQL 인스턴스
- DB 연결: RDS 보안 그룹이 EC2 보안 그룹에서 오는 3306 연결만 허용
- 스키마: 애플리케이션 시작 시 Flyway V1~V8 검증 및 적용
- JPA: 운영 환경에서 `ddl-auto=validate`

## 검증 결과

- 서비스 실행 상태와 `/api/health` 응답 확인
- 인증, 현장, 공정, 보고서, 자재 요청, 알림, 디바이스 토큰 흐름 확인
- 비회원·권한 부족·중복 요청의 오류 상태 확인
- 배포 검증 중 생성한 RDS 테스트 데이터는 초기화 완료
- 현재 RDS는 Flyway 스키마만 있고 업무 데이터는 없는 상태

## 현재 제한

- HTTPS와 도메인 미적용
- API 8080 포트의 접근 범위를 보안 그룹으로 제한 중
- 사진·첨부파일의 실제 원본 저장소 미구현
- FCM 푸시 발송 미구현
- 자동화된 전체 API 회귀 테스트 미완성

> 이 문서는 기능 범위를 설명합니다. 실제 접속 주소와 비밀정보는 저장소에 기록하지 않습니다.
